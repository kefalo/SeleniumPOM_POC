# SeleniumPOM_POC

A QA automation project built as part of my portfolio, focused on building a maintainable test automation framework using **Python, Selenium, Page Object Model (POM), Pytest, and Allure**.

The goal of this project is to demonstrate the process of building a UI automation framework from the ground up — from the initial project structure and framework components to test execution, reporting, debugging, and future improvements.

## 🛠️ Tech Stack

* **Python**
* **Selenium WebDriver**
* **Pytest**
* **Page Object Model (POM)**
* **Allure Report**
* **Git / GitHub**

---

## 📋 Project Roadmap

The project is planned to be developed in the following order:

### 1. Project Setup

* Create the initial project structure
* Define the libraries and dependencies that will be used
* Set up the Python virtual environment
* Configure the initial project settings

### 2. Project Structure

* Create the `Pages` and `Tests` directories
* Define the overall framework structure
* Establish a clear separation between page objects and test cases

### 3. Framework Foundation

* Define `conftest.py`
* Create the `BasePage` class
* Implement common methods and utilities
* Define fixtures and shared configurations
* Establish the initial framework conventions

### 4. Initial Test Execution

Once the basic framework is ready:

* Select a suitable dummy/demo website
* Create a few basic tests
* Verify that the framework can successfully execute tests
* Validate the overall framework structure before expanding it

### 5. Page Objects & Locators

* Map the relevant objects from the selected application
* Create and organize locators
* Implement page-specific methods
* Apply the Page Object Model consistently

### 6. Dependencies & Configuration

* Review and update the libraries being used
* Define project dependencies
* Improve configuration where necessary

### 7. Test Development

Start building the actual test suite using:

* Pytest
* Page Objects
* Fixtures
* Test markers
* Allure reporting
* Reusable framework components

### 8. Test Execution & Reporting

Execute the tests in both:

* **Headless mode**
* **Non-headless mode**

Analyze:

* Test execution results
* Console output
* Logs
* Allure reports
* Failed test behavior

### 9. Debugging & Improvements

Improve the framework with a focus on:

* Easier debugging
* Better error handling
* Better logging
* Troubleshooting failed tests
* Code readability
* Maintainability
* Framework scalability

---

## 🎯 Project Goal

The main goal is not simply to create a collection of Selenium tests, but to understand and demonstrate how a **real-world UI automation framework** can be structured and developed step by step.

The framework will evolve throughout the project, with improvements and refactoring being introduced as new requirements and problems are identified.
